
## d1s1 The four properties architects design around  (12 q)
- d1s1q01 [nexttoken-precision] Which category of output is most at risk of looking accurate while being wrong, because Claude generates text by predicting likely continuations?  => Specific names, dates, citations and statistics
- d1s1q02 [nexttoken-precision] A claims assistant must pull the policy start date and claim amount from each document. Which design response best addresses the next-token-prediction limitation?  => Verify extracted values against the source of truth with code-based checks
- d1s1q03 [demo-not-determinism] A team saw a reconciliation demo produce identical categorizations five times and shipped with no output checks. In week two, re-processing the same statement gave a different category. What is the root cause?  => The model was treated as deterministic when it is not
- d1s1q04 [demo-not-determinism] An architect asks why evaluation frameworks are needed if a prototype already behaves well in front of stakeholders. Which answer reflects the right reasoning?  => Behavior observed once cannot be certified for a non-deterministic system

- d1s1q06 [context-limit-errors] A request is accepted, but the response stops early with a model_context_window_exceeded stop reason and truncated output. What happened?  => The prompt fit, but generation ran into the window ceiling
- d1s1q07 [knowledge-external-truth] A legal-research tool must answer questions about a regulation amended last month. Which mitigation fits the knowledge property best?  => Use retrieval or tools so the current source is authoritative
- d1s1q08 [knowledge-external-truth] Which statement best describes how Claude behaves when asked about a rare or fast-changing topic outside its reliable knowledge?  => It may give stale or incomplete information in its usual confident tone
- d1s1q09 [working-memory-mitigation] A support assistant's conversations are growing long and critical instructions are being lost. Which TWO working-memory mitigations apply? Select TWO.  => Front-load the critical information in context / Summarize across turns as context grows
- d1s1q10 [confidence-not-validity] Why are human-in-the-loop placement and verification described as architectural choices rather than afterthoughts?  => Claude's wrong answers look as fluent and assured as right ones
- d1s1q11 [steerability-limits] Which TWO task types does the steerability property flag as places where Claude can drift from intent? Select TWO.  => Abstract or ambiguous instructions / Tasks requiring precise numerical or logical computation
- d1s1q12 [steerability-limits] A finance workflow needs exact totals across thousands of invoices, and the model sometimes follows the letter of an instruction but misses its intent. What is the best design response?  => Let deterministic computation or tool execution own the totals

## d1s4 Pattern selection  (13 q)
- d1s4q01 [three-patterns-definition] What makes a system an agent rather than a workflow?  => The model chooses its own sequence of steps toward a goal
- d1s4q02 [three-patterns-definition] A single model call is given retrieval and a tool, and the control flow never branches on what the model decides. Which pattern is this?  => Augmented LLM, one bounded call with helpers
- d1s4q03 [workflow-subpatterns] A due diligence review sends each of twelve supplier contracts to a separate simultaneous call, then aggregates the results into one risk report. Which sub-pattern is this?  => Parallelization
- d1s4q04 [workflow-subpatterns] A model drafts a complaint response, a second call grades it against a rubric, and the loop repeats until every rubric item passes or a retry limit is hit. Which sub-pattern is this?  => Evaluator-optimizer
- d1s4q05 [workflow-subpatterns] Support tickets arrive and a classifier sends billing questions to account-data retrieval, technical issues to product-documentation retrieval, and escalations to a human queue. Which workflow sub-pattern does this show?  => Routing
- d1s4q06 [five-factor-framework] In the five-factor framework, how should the architect apply the factors when choosing a pattern?  => Walk them in sequence; the first factor that rules out a pattern decides
- d1s4q07 [agent-when-justified] When is an agent the right pattern, according to the notes?  => When the steps genuinely cannot be determined in advance and unexpected output is recoverable
- d1s4q08 [agent-when-justified] A team's mined traces showed only four distinct paths through their system, yet they had built an agent. What should they have built?  => A router with four chains
- d1s4q09 [agent-constraints] Which THREE are constraints a production agent is typically bound by? Select THREE.  => Explicit permissions on what each tool is allowed to do / Constrained tool entry points limiting what the agent can reach / Per-turn budgets together with explicit stopping criteria
- d1s4q10 [prompt-before-finetune] Prompting feels unreliable on a classification task. What is the recommended order of escalation?  => Optimize the prompt, add tools or retrieval, try evaluator-optimizer, then fine-tune
- d1s4q11 [prompt-before-finetune] Which TWO situations justify considering fine-tuning? Select TWO.  => Latency is critical and a smaller specialised model would beat a prompted one / The task runs at very high volume and inference cost is the constraint
- d1s4q12 [governance-gap] An auditor asked which model version approved a disbursement, and the trace showed the version had rolled forward two weeks earlier without re-validation. What kind of failure is this?  => A model-governance gap any pattern would have inherited
- d1s4q13 [skills-packaging] The same claims-review procedure must run across several teams and products, be versioned, and be governed as one unit. Which packaging option fits?  => A Skills-based architecture packaging the procedure and scripts

## d1s5 Multi-agent systems and reference architectures  (13 q)
- d1s5q01 [orchestrator-role] What is the orchestrator's job in a multi-agent system?  => Own the goal: decompose, delegate and synthesize results
- d1s5q02 [fanout-pattern] A regulatory filing must be checked against fifty rules, too much for one context. Which design is the standard fan-out shape?  => Split into independent units, one subagent per unit, then synthesize
- d1s5q03 [recoverable-vs-unrecoverable] Which failure is described as usually recoverable, and which as often unrecoverable?  => Subagent failure is recoverable; orchestrator losing state is often unrecoverable
- d1s5q04 [coverage-check] A 50-section contract review reported '48 sections reviewed, 3 flagged', but two subagents had timed out or returned empty. Which control would have caught this?  => A coverage check at synthesis: results returned must equal units dispatched
- d1s5q05 [coverage-check] Which THREE gaps combined to let the dropped sections go unnoticed in the 50-section review? Select THREE.  => The count was never reconciled between units dispatched and results received / Nothing owned the subagent boundary to retry or flag failed units / The summary read as complete and fluent, masking the gap
- d1s5q06 [shared-trace-id] Traces fragment across an orchestrator and its subagents, so a single run cannot be reconstructed. What is the design response?  => Propagate a shared trace identifier across all agents
- d1s5q07 [hitl-checkpoint] Where should a human-in-the-loop gate sit in a multi-agent system?  => Before any irreversible or high-stakes action a subagent takes alone
- d1s5q08 [rag-live-state] A retail assistant using RAG answers 'Your order shipped on the 12th' although the order was returned to depot. The index held two stale snapshots. What is the correct fix?  => Call the order-status service directly through a tool
- d1s5q09 [rag-live-state] Which description matches the retrieval principle from the notes?  => Retrieval is for stable knowledge; tool use is for live state
- d1s5q10 [architecture-failure-modes] A document processing pipeline sends low-confidence extractions through the same flow as clean documents. Which failure from the reference architectures is this?  => No exception path or human gate for low-confidence extractions
- d1s5q11 [architecture-failure-modes] Which TWO are named failure modes for the coding agent and customer-service routing reference architectures? Select TWO.  => Letting the agent edit and commit without a human review gate / Using retrieval for live order status instead of calling the API
- d1s5q12 [one-vs-several-patterns] When is it justified to combine a second reference architecture with the first?  => When two parts of the problem break in different ways worth managing separately
- d1s5q13 [one-vs-several-patterns] A routing workflow that hands some intents to an agentic loop is evaluated with a single end-to-end eval set. What is the risk?  => A healthy top-level score can mask failures in one component

## d1s6 Feasibility, sizing and business value  (14 q)
- d1s6q01 [scoping-sequence] Which is the correct order of the scoping discovery sequence?  => Requirement, capability list, architecture sketch, boundary conditions, SOW
- d1s6q02 [scoping-sequence] A scoping document says the system works for documents up to 20 pages but fails beyond that. Where should this limit be recorded?  => In the SOW as a boundary condition
- d1s6q03 [sizing-inputs] Which three inputs form the basis of the monthly cost estimate before any code is written?  => Call volume, token budget per request, and model tier
- d1s6q04 [token-distribution-tail] A cost model used the average document's token count. After launch, the longest documents consumed most of the token spend. What was the modelling error?  => Assuming a uniform distribution instead of modelling the tail
- d1s6q05 [token-distribution-tail] Why is p95 a better latency design target than the median?  => SLA breaches are usually caused by the slowest requests at the high end
- d1s6q06 [feasibility-verdicts] A design works only if document length stays under a threshold and the retrieval index is refreshed on a defined schedule. Which verdict is this, and what must be done?  => Feasible with constraints; document each constraint and its failure mode
- d1s6q07 [feasibility-verdicts] At least one capability faces a property limitation that cannot be compensated within scope and budget. What should the verdict document?  => The disqualifying constraint, and any scope reduction that changes the verdict
- d1s6q08 [four-properties-feasibility] Match feasibility questions to properties: which TWO are correct pairings? Select TWO.  => Steerability: are the instructions specific, concrete and verifiable? / Working memory: do the inputs fit the context window in aggregate?
- d1s6q09 [roi-mapping] Which sequence correctly describes the four-step ROI mapping?  => Name the baseline in a business unit, predict the post state in that unit, subtract run cost, state payback with sensitivity
- d1s6q10 [roi-errors] A value case assumed claims review labour disappears entirely, yet the design includes a human review gate for low-confidence outputs. What happens after launch?  => Actual analyst hours fall less than the business case promised
- d1s6q11 [roi-errors] Which TWO are among the most common ROI map errors? Select TWO.  => Taking run cost from an average rather than the distribution / Estimating the baseline instead of measuring it
- d1s6q12 [five-value-pillars] Which list names the five value pillars used to frame an ROI claim?  => Efficiency, transformation, productivity, solution cost, performance SLAs
- d1s6q13 [contracts-scoping-call] A partner reveals 800 contracts a day, some of 300 pages, with a 30-second requirement. What does the notes' analysis conclude about volume and latency?  => Volume is about one request per 108 seconds, so it pressures cost, not latency
- d1s6q14 [contracts-scoping-call] In the contracts call, what was the architect's core mistake?  => Issuing the feasibility verdict before gathering volume, size and latency

## d2s1 Model selection and gating model changes  (13 q)

- d2s1q09 [per-step-tiering] After the overrun, which per-step assignment did the retroactive eval support?  => Haiku for routing, Sonnet for mid-pipeline summarization, Opus for final composition
- d2s1q10 [thinking-billing] Which statement about extended thinking is accurate?  => Thinking tokens are billed as output tokens and add latency to the call.
- d2s1q11 [thinking-budget-tokens] A team sends a manual budget_tokens thinking configuration to Claude Sonnet 5 and gets an HTTP 400. What is the correct remediation?  => Switch to adaptive thinking and set the effort parameter instead.
- d2s1q12 [thinking-measured-gap] A product lead wants extended thinking on every call 'since it can't hurt'. What is the best architect response?  => Run evals without it first; enable it only if a measured accuracy gap remains.
- d2s1q13 [thinking-measured-gap] In the 7x overrun case, where did extended thinking add cost and latency with no benefit?  => On the routing classifier, which did not need reasoning at all.

## d2s2 Context window and context strategy  (14 q)
- d2s2q01 [no-native-memory] A support chatbot must remember a customer's earlier sessions. Which statement correctly describes where that continuity comes from?  => The application stores summaries and passes them back into each new call.
- d2s2q02 [state-needs-tool-call] An assistant must report a customer's current order status and account balance. What is the correct design?  => Expose a tool call that fetches the live records from the system of record.
- d2s2q03 [working-memory-cliff] Why is the context window described as having a 'working-memory cliff'?  => Things work until the limit, then fail abruptly; outside the window nothing exists.
- d2s2q04 [budget-ceiling] How should an architect size the token budget for a multi-turn assistant?  => Size for the largest realistic conversation plus retrieval, prompt, scratch and margin.
- d2s2q05 [budget-ceiling] A team plans to let conversations grow until the window is nearly full because 'we paid for the space'. What is the main flaw?  => It hits the cliff in production, and every token is billed on every call.
- d2s2q06 [measure-usage] How should a team find out how many tokens a request really consumed?  => Read the actual token counts in the API response usage field.
- d2s2q07 [measure-usage] Which TWO practices correctly handle token measurement in a production sizing exercise? Select TWO.  => Treat any fixed characters-per-token ratio as a rough illustration only / Record measured usage and use it for limit and cost planning
- d2s2q08 [strategies-combine] In a long-running coding agent, which TWO pairings of phase and strategy match sound design? Select TWO.  => Session start: a small, stable monolithic prefix suited to prompt caching / Active work: carry forward only recent state progressively
- d2s2q09 [strategies-combine] Why can a long-running coding agent not be served by any single context strategy?  => Each strategy handles a different dimension, so they work as layers.
- d2s2q10 [monolithic-creep] A document pipeline starts conversations with a 4,000-token prompt and sees costs rise with no code changes. By turn 30 the context holds about 80,000 tokens. What is the likely cause?  => Monolithic accumulation across turns is silently inflating per-call input.
- d2s2q11 [retrieval-earns-place] For which TWO situations is retrieval (RAG) the strongest context strategy? Select TWO.  => Sources that change faster than the prompt is redeployed / Knowledge bases too large to fit in context
- d2s2q12 [compaction-lossy] A long-running agent compacts its transcript, and later a decision depends on an exact order number mentioned once early on. What is the most likely issue?  => The summary dropped the load-bearing identifier; compaction is largely one-way.
- d2s2q13 [compaction-lossy] Which risk is specific to compaction as a context strategy?  => The summarizer is a model call, and its fidelity is hard to measure.
- d2s2q14 [strategy-vs-sizing] A design review conflates context strategy with context sizing. Which TWO statements correctly separate them? Select TWO.  => Sizing sets how much window to use; strategy sets how context arrives / The two decisions interact but do not determine each other

## d2s3 System prompts, templates and technique selection  (13 q)

- d2s3q02 [template-safe-default] What is the main design goal of a prompt template with fixed scaffolding and parameterized slots?  => Filling a slot cannot remove a constraint, so the safe path is default.

- d2s3q04 [underspecification-improvises] A reused prompt says 'summarize the ticket' and the summaries vary in length and structure from call to call. What is the underlying failure?  => The prompt is underspecified, so the model fills gaps with different assumptions each time.
- d2s3q05 [underspecification-improvises] A reviewer asks, for each requirement the output must meet, whether the prompt states it or merely hopes for it. What is this diagnosis for?  => Finding underspecification gaps the model will fill differently each time
- d2s3q06 [guardrail-underspecified] A prompt includes the line 'be careful with sensitive data'. Why might this be worse than having no guardrail at all?  => It looks like a control but has no substance; the model can route around it.

- d2s3q08 [technique-progression] A team needs to extract structured fields from invoices and a first prompt has not been tried yet. Which approach follows the recommended progression?  => Start zero-shot; add examples only if format or judgment needs showing.
- d2s3q09 [technique-progression] Why is applying chain-of-thought to a simple classification task a design flaw?  => It is a recurring token and latency tax with no gain.
- d2s3q10 [prompt-model-pairing] A team swaps a mature prompt from one model generation to a newer tier and finds output quality has shifted. What principle explains this?  => The prompt-model pairing is what ships, so a swap needs an eval.
- d2s3q11 [prompt-model-pairing] Which TWO statements about prompts across model tiers are accurate? Select TWO.  => A more capable model may need less scaffolding to reach the same quality / A less capable model may need more examples or explicit steps
- d2s3q12 [bias-unbalanced-examples] A few-shot classifier over-predicts 'approve' in aggregate. Which TWO prompt-construction faults are most likely responsible? Select TWO.  => Examples that show mostly approvals and few other cases / Leading phrasing that presumes the answer is 'approve'
- d2s3q13 [stale-few-shot] Six months after launch, a few-shot extraction prompt starts mishandling a new document layout even though nothing in the code changed. What is the most likely first thing to review?  => The few-shot examples, which may be stale against the evolved task

## d2s4 Prompt caching, modular prompts and Skills  (16 q)
- d2s4q01 [cache-stable-prefix] On what basis does prompt caching match a request to a stored entry?  => A stable, identical prefix of the prompt
- d2s4q02 [cache-never-hit] A team put per-request document text at the top of a prompt, ahead of a large fixed instruction block, and saw no caching savings. What is the fix?  => Place fixed content first and dynamic content last.
- d2s4q03 [cache-never-hit] An application sends the same 8,000-token system prompt and policy document on every request, followed by a short varying user message. Which optimization most directly reduces both latency and cost?  => Put static prompt and policy before dynamic content, and enable prompt caching.
- d2s4q04 [cache-breakpoint] What is the purpose of a cache breakpoint?  => To mark where the fixed cacheable prefix ends and variable content begins
- d2s4q05 [cache-ttl-frequency] The default cache TTL is 5 minutes. A workload calls the same long prompt once every 20 minutes. What is the likely outcome?  => No consistent savings, because entries expire between calls and writes repeat.
- d2s4q06 [cache-economics] If cache reads cost 10% of the standard input rate and writes cost more than standard input, when does caching produce the largest savings?  => A long, stable prefix reused across many requests within the TTL
- d2s4q07 [cache-not-worth] In which TWO situations is enabling prompt caching likely to cost more than it saves? Select TWO.  => The fixed portion of the prompt is small / The prompt is called infrequently, so the write is rarely amortized
- d2s4q08 [cache-response-identical] A stakeholder worries that prompt caching will return stale or altered model answers. Which statement is accurate?  => Caching stores the prompt prefix; the response matches an uncached call.
- d2s4q09 [consistency-window] A team caches a prefix that includes a live inventory snapshot, and answers sometimes reflect outdated stock levels. What risk was overlooked?  => Caching created a consistency window where cached content lags live state.
- d2s4q10 [library-vs-skill] A procedure must run the same way across several products, with versioning, approval and rollback. Which reuse approach best fits?  => A Skill, packaged as a versioned self-contained unit
- d2s4q11 [library-vs-skill] An engineering team within one codebase assembles and frequently tweaks prompt fragments, with light governance. Which approach is the better fit?  => A modular prompt library owned by the engineers
- d2s4q12 [skill-packaging] What does a Skill package together?  => A SKILL.md with instructions, optional scripts and version management
- d2s4q13 [ungoverned-drift] A prompt is copy-pasted across five teams, each adjusting it slightly. Which risk does this most directly create?  => Many slightly different versions drift apart, each with quietly different behavior.
- d2s4q14 [cache-ttl-frequency] With the default 5-minute TTL, which TWO workloads will realize consistent caching savings? Select TWO.  => A long stable prefix called several times every minute / A long stable prefix called steadily every few seconds
- d2s4q15 [cache-economics] Why must a caching cost model include the first request on a new prefix?  => Cache writes carry a higher per-token cost than standard input on first use.
- d2s4q16 [consistency-window] Which prompt is the riskiest candidate for caching in its entirety?  => A prompt whose prefix embeds an hourly-changing price table that answers must always reflect
